# CAPE-Plan v0.2: Selective, time- and issuer-constrained evidence acquisition

**2026-11-24 reproducible CPU algorithm artifact.** The implementation is independent research, not an officially accepted PALE task or an externally benchmarked improvement.

## Research problem

A personal agent may claim a complex action has succeeded. Confirming the claim requires several independent, service-issued records (for example consent, accessibility route, dispatch delivery and a currently active authorization grant). Each verifier-controlled read-only query costs time or money; the auditor has a limited evidence budget. A naive maximization of *the number of facts fetched* fails because a goal is verified only when **all** its necessary facts are current, from allowed issuers, value-consistent and scope-bound.

Let `G` be verification goals. A goal `g` has a positive weight `v_g` and a conjunction of evidence obligations `N_g`. A witness is keyed by `(token, value, issuer, at)`. A query `q` has a positive integer cost `c_q`, a declared authenticated service channel, and a hypothetical set of returned witnesses. Given already authenticated trusted receipts `R_0`, an auditor with budget `B` selects a set of queries `S`:

\[
\max_{S\subseteq Q,\ \sum_{q\in S}c_q\le B}
\sum_{g\in G}v_g\cdot \mathbf1\{\text{all needs of }g\text{ are satisfied by }R_0\cup R(S)\}.
\]

Each need has an expected typed value, an allowed issuer set, and an inclusive freshness window. For a need, only the **latest** qualified timestamp counts; if the latest authorized witnesses disagree or disagree with the expected value, it remains unproven. Scope is encoded by a unique obligation token. The planner rejects non-read-only candidate queries and requires each candidate receipt's claimed issuer to equal its declared channel. A live runtime must independently authenticate the channel.

**Critical trust boundary:** query returns are predictions used solely to plan future read-only checks. No selected query, predicted witness or score establishes that an actual tool call happened, that the underlying service-side log is complete, or that a task succeeded. After acquisition the verifier must re-run CAPE-Graph against real trusted receipts and all committed side effects. The same observed facts cannot resolve worlds differing only by unlogged effects.

## Algorithm and optimization guarantee

`solve_exact` performs deterministic branch-and-bound on up to 20 candidate queries. Query subsets are evaluated against the latest conflicting permitted issuer evidence, not mere token membership. An optimistic bound checks whether every unmet need could in principle be supplied by a selected or remaining candidate; it ignores acquisition cost and adverse evidence and therefore **cannot underestimate the best reachable reward**. If the optimistic remaining reward is below the incumbent, the branch can be pruned safely. Over-budget branches are excluded. The lexicographic objective is **(maximize verified-goal reward, minimize query cost, deterministic tie-break by selected query identifiers)**. It is exact within the finite, enumerated query set, with worst-case exponential complexity. The `optimal` output refers only to this well-defined finite optimization, **not** to optimality of real-world task execution.

A separate exhaustive oracle enumerates all subsets up to 15 queries and computes each goal's satisfaction independently; it is not the production branch-and-bound routine. The baseline `greedy_marginal` accepts only queries with positive immediate *completed-goal* gain per cost. This baseline is deliberately transparent and simple; it is not a published state-of-the-art planner.


The experiment includes **three explicitly constructed conjunctive counterexamples** and **360 deterministic out-of-fixture synthetic environments** generated from the fixed seeds `20270201 ... 20270560`. Each trial includes 2–6 goals, 3–10 query candidates, query costs, trusted issuer/outsider distinctions, stale/fresh timestamps and potentially conflicting values. The independent exhaustive oracle checks the exact solver on every trial; the myopic greedy baseline uses the same query set, budget and evidence data.

All 363 queries-of-queries trials are synthetic and generated by the study authors. No observed agent behavior, actual credentialed service query, independent human QA or representative distribution is claimed. ## What this adds and what it does not

The **implemented** algorithm solves a budgeted, conjunctive proof completion problem with source/time scopes, latest-state conflicts, and cost-sensitive exact optimization. This produces a concrete acquisition plan, complete/pending goal separation, exhaustive-oracle checks, deterministic evidence-set tie-breaking, and easy-to-falsify constraints. It composes with CAPE-Graph's action-effect verifier while keeping the candidate's observations separate from verifier-only truth.

Set cover, branch-and-bound, constraint synthesis, active testing and three-valued verification existed before this prototype. The claim of **publication-level new theory** is not established. To establish novelty and practical SOTA, compare with risk-based verification schedulers and adaptive testing systems on independently collected agent sessions; measure the query-cost/risk/false-rejection Pareto frontier, withheld unknowns, misspecified issuer registries, timing drift, and alternative valid policies. The 2027 direction is counterexample-guided synthesis of *these obligations* from trusted tool schemas, and the 2028 direction is an adaptive proof-carrying reward with feedback learned from trusted executions; both remain unimplemented hypotheses.

## Relationship to current literature

- AgentSuite (ICML 2026) studies reliable agent evaluation through benchmark auditing and component-level checks, beyond simple score correctness.
- VerifierBench (October 2026, arXiv:2610.28679) evaluates executable agent verifiers on alternative valid solutions and adversarial cases. It is a key required comparator for later external testing.
- Do Agent Benchmarks Do What They Say? (arXiv:2609.37315) shows why execution contracts and provenance matter; do not claim these ideas as newly discovered.
- ICLR 2026's Gaia2 verifier already uses causality, timing and completeness. Our contribution is **a separate bounded evidence-acquisition optimization experiment**, not an invention of those criteria.
