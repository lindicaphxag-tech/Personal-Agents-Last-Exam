# Symbolic interval reachability for bounded walking (research reference)

Instead of propagating every event boundary, maintain a union of half-open integer arrival-time intervals for each (node, exact distance spent). Start with the singleton [departure,departure+1) at the source and distance zero. For edge e with duration d and cost c, intersect the reachable intervals with its availability windows and the remaining deadline, shift by d, and union into the destination's distance+c state. Re-enqueue a state only when its union increases. Intervals are merged when overlapping or adjacent. The target is absorbing (any walk reaching it earlier is already a solution). This is an exact finite-state reachability abstraction: all propagated times have real predecessor paths; conversely induction on path length shows that every feasible walk is represented at the least fixed point. Zero-cost zero-time cycles cannot increase a union forever because the state space is finite. Pick the minimum reachable target time, then the minimum exact cost. Backward search in the stored reachable sets reconstructs a witness; visited triples prevent zero-cost cycles. Limits on states/interval storage and counted work report incomplete, never infeasible. No claim that the implementation is polynomial in bit-length or that compressed unions remain small on arbitrary graphs. Interval storage can fragment; cyclic networks can require many updates. The work counter counts edge-window transforms and reverse witness edge inspections, not every comparison in interval merging or input processing.

The previous event-equivalence solver remains unmodified. This is a different exact reference strategy (forward symbolic reachability rather than event partitioning). Known integer time, nonnegative integer costs, fixed travel duration, no waiting, entry-time windows, finite horizon. The existing walking-only adapter is reused; this is NOT the production Hopline App, a general transit planner or a patch on #171. Related background: multiobjective temporal path label setting, https://doi.org/10.1002/NET.22253; time-dependent waiting-policy routing, https://people.csail.mit.edu/bdean/journal-waiting.pdf. No general novelty claim.

Validation: 9 assertion groups, 2000 random graph instances, 441 feasible, 991 containing windows, 616 containing zero-duration zero-distance edges. Both the new and pinned exact-time solver matched independent discrete-state reachability; every returned optimal witness replayed. Four walking fixture checks used the original pinned seed and prior adapter. Stress case is deliberately structured: binary duration choices yield contiguous integer time sets; this favors interval merging and is not representative performance. Compare all three methods and their full wall-clock elapsed times including setup and witness; three fixed repetitions, integer-millisecond JS clock in the tool execution environment, hardware unspecified, noisy and not a production benchmark. Work counters differ by algorithm and must not be treated as equal-cost operations. The random-case totals also expose the potential overhead of exploring all reachable states. No Node wrapper, full App CI, or model evaluation was run here; the exact function bodies and fetched pinned prior modules were executed in the JS environment. Reproduce with node test_interval_walk.cjs. No change to approved task proposal or another contributor's branch, no external acceptance or authorship claim.
